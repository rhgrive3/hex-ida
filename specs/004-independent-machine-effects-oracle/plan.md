# Implementation Plan: Independent MachineEffects Oracle

**Branch**: `spec/hex-me-01-readiness` | **Date**: 2026-08-28 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/004-independent-machine-effects-oracle/spec.md`

## Summary

HEX-ME-01 adds a genuinely independent, offline evidence path for MachineEffects instruction
semantics. It treats the canonical production effect bundle as the subject under comparison and
uses independently generated expected state plus per-observable defined masks. Versioned case,
result, provenance, and report identities make stale, malformed, partial, and common-mode evidence
fail closed. The work remains under `tools/validation/machine-effects/**` with validation under
`tests/machine-effects/**`; it does not modify production effects, expected tables, C0-01
manifest/profile contracts, A2 denominator declarations, downstream semantic engines, workflows,
or generated release output.

## Technical Context

**Language/Version**: Node.js 22 ES modules; `BigInt` for fixed-width machine values

**Primary Dependencies**: Existing canonical MachineEffects bundle/normalization exports; existing
offline external-oracle policy and differential/report helpers; independently versioned ISA,
hardware, emulator, or reference sources supplied by the validation environment. No new runtime
dependency is required by this planning phase.

**Storage**: Versioned JSON/JSONL corpus and evidence artifacts under the validation ownership
surface; CI artifacts are temporary and must be validated before publication.

**Testing**: Node test runner with explicit T0/T1/T2 tests under `tests/machine-effects/**`, plus
permanent exact-SHA and candidate-merge-tree verifier invocations. Long architecture-wide suites
are deferred until the early contract is approved.

**Target Platform**: Offline Linux/Node 22 validation environment and CI; browser/iOS consumes
frozen evidence and is not an oracle runtime.

**Project Type**: Validation tooling and release-evidence library for a compiler/analysis product

**Performance Goals**: Every case has declared time, input, output, memory, and case-count bounds;
the initial proof matrix is small and deterministic. A budget or cancellation event must terminate
as explicit non-pass evidence.

**Constraints**: No production semantic changes; no second production evaluator; no C0-01
manifest/profile edits; no A2 denominator edits; no generated output or workflow changes; no
default runtime network; all gaps and unavailable authorities remain explicit; Sol owns moving-main
reconciliation, committed generated output, and cutover.

**Scale/Scope**: v1 names four current profiles—ARM64/A64, ARM64e/A64+PAC, x86_64/long-64, and
RISC-V64/RV64IMC—with the deterministic add counterexample, required negative matrix, replay
proof, and at least one real-ISA evidence case per promoted profile. Full ISA breadth is out of
scope until independently evidenced.

## Phase 0: Research decisions

Research is recorded in [research.md](research.md). The resolved decisions are:

1. Consume `createMachineEffectBundle`/`validateMachineEffectBundle` output as the subject; do not
   reuse it or its expected tables as oracle truth.
2. Use a versioned case/result/report contract with per-observable masks and digest-bound identity.
3. Keep ISA/specification and independent execution/reference sources as semantic authorities;
   retain compiler, Ghidra, and Capstone in their narrower declared roles.
4. Enumerate the current four profiles and preserve unsupported/unavailable gaps.
5. Keep all implementation and validation changes under the offline owner surface; existing
   `independent-oracle.mjs` scalar/address helpers remain support code, not proof authority.
6. Bind exact product/candidate, verifier, corpus, oracle, toolchain, and generated identities.
7. Stage T0/T1/T2 before any long corpus suite or release promotion.

## Implementation Boundary and Ownership

- **Feature owner**: `tools/validation/machine-effects/oracle-schema.mjs`,
  `oracle-corpus.mjs`, `oracle-runner.mjs`, `oracle-report.mjs`, and the five focused validation
  tests above, subject to Sol approval after this spec-ready checkpoint.
- **Read-only subjects**: canonical production effect bundle APIs, existing scalar/address helper,
  existing compatibility differential, external-oracle policy, and A2 denominator.
- **Integration owner (Sol)**: moving-main reconciliation, generated release output, exact-head
  workflow dispatch, candidate merge-tree proof, merge, and durable ledger updates.
- **Forbidden**: production evaluator/expected-table edits, C0-01 manifest/profile edits, any
  MemorySSA/points-to/summary/decompiler edits, unrelated workflow/generated changes, and Issue or
  Gemini lifecycle changes.

## Validation and Evidence Invalidation

T0 must fail before implementation, then pass only with a distinct oracle and independent expected
state. T1 must reject all required negative cases and prove two-run deterministic replay. T2 must
preserve A2 exactly and bind every identity. Any change to the product/base relationship, verifier
or schema, corpus/generator, oracle/toolchain, profile set, or generated artifact invalidates the
affected evidence and requires a fresh exact-head/candidate-tree run. A green historical component
head cannot substitute for the actual candidate tree.
