**Execution rule**: The checkbox and `Status` change only from actual evidence.
Every task uses one implementation owner. Workers do not spawn workers. SOL Ultra
is the living integration, generated-output, merge, and final evidence owner.
`contracts/task-ownership.json` MUST contain exactly one nonempty `allowedPaths`
array and one nonempty `forbiddenOverlap` array for every task ID. A missing,
duplicate, empty, or concurrently violated entry blocks task assignment and
promotion; sequential path reuse requires its dependency owner's completed
exact-tree handoff.

older `independent Sol review`, `separate Sol review`, or equivalent reviewer
label below is superseded by an independent Luna Max review. Sol may still own
high-risk semantic implementation, but it is not the campaign review model;
SOL Ultra remains the final semantic, integration, and merge authority.

`integration-inventory.json`, then hands it to T049 through an exact-tree,
dependency-ordered integration checkpoint. Component branches are named
`component/final-closure-tNNN-*`, target the current living integration branch,
and MUST NOT edit that inventory. Their tests and verifier run on the exact
candidate merge tree. After each acceptance, T049 refreshes the cumulative
main-to-integration inventory, canonically regenerates integration-owned output,
requires a second zero-diff generation, runs the rolling product/verifier gates,
and records the checkpoint before another component merge. Stage B transfers

checkpoint transaction to every accepted Stage B residual lane.

candidate gate is the task group discovered below
`tests/final-closure/tNNN/**`. The `shadow` argv invokes the registry-fixed

projection. Providers emit raw observations only. The central verifier derives

components cannot choose or modify any acceptance authority through their
report. Implementation self-agreement is not independent proof. Missing task
tests, pinned contract/provider, case, counter, or valid central-verifier receipt
