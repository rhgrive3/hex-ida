PROBLEM: source-backed ELF parsing (js/binary/source-loaders.js parseELFSourceWithPrefix -> js/binary/source-reader.js parseSourceRanges) runs the synchronous parser against a sparse byte cache and RESTARTS THE WHOLE PARSE on every cache miss. For a 23.7 MB AArch64 C++ binary (OpenMW) this takes 22 parser passes x ~3.5 s = ~80 s. A full-bytes parse takes 2.8 s.

GOAL: cut the number of parser passes for ELF to a small constant without changing parse results and without exceeding the existing metadata budget (maxCachedBytes).

Design (do this): before the first full parser pass for ELF, deterministically prefetch the metadata ranges that the parser will need, derived only from the ELF header, program headers and section headers (all bounded reads):
 - ELF header, program header table, section header table, .shstrtab
 - PT_DYNAMIC segment bytes; then from DT_* tags: DT_SYMTAB..(size from section header of SHT_DYNSYM if present, else from DT_GNU_HASH/DT_HASH derived count), DT_STRTAB+DT_STRSZ, DT_RELA+DT_RELASZ, DT_REL+DT_RELSZ, DT_JMPREL+DT_PLTRELSZ, DT_VERSYM/DT_VERNEED/DT_VERDEF, DT_GNU_HASH/DT_HASH, DT_RELR
 - section headers of type SHT_DYNSYM, SHT_DYNAMIC, SHT_STRTAB (linked from dynsym/symtab), SHT_SYMTAB, SHT_RELA/SHT_REL, SHT_GNU_versym/verneed/verdef, SHT_GNU_HASH/HASH, SHT_NOTE, .eh_frame_hdr, .gnu_debuglink, .comment are candidate ranges.
 Only prefetch ranges that fit in the remaining maxCachedBytes budget; if the sum would exceed the budget, prefetch in priority order and stop (parsing then continues with the normal miss/restart loop, so correctness never depends on prefetch). Use the existing `initial` mechanism (options.initial items {offset, bytes}) or add a prefetch hook in parseSourceRanges that coalesces adjacent ranges (merge gaps < 64 KiB) into few large reads, respecting source.maxReadLength and maxReads.
 Parser outputs must be byte-for-byte identical with and without prefetch.
