GOAL: speed up js/decompiler/passes/manager.js `isDeepImmutable` and `capturePassState` without changing rollback semantics.

Measured problem: capturePassState is called before every optional pass; on __addtf3 it takes 2.5 s (123,843 records) and isDeepImmutable 1.8 s self time. Root cause of isDeepImmutable cost: it caches only the ROOT value's answer. capturePassState calls isDeepImmutable(value) for every object it visits; for a frozen object whose subtree contains one mutable leaf, every frozen ancestor re-walks its whole subtree (quadratic). Also each call allocates a new Set.

Required change:
1. Rewrite isDeepImmutable as an iterative post-order DFS that caches the answer for EVERY visited node (WeakMap deepImmutableCache). Exact cycle handling: use Tarjan-style SCC (or equivalent) so that nodes in a strongly connected component get one shared answer; never cache `true` for a node whose answer could depend on an unfinished on-stack node. Caching `false` conservatively is always safe (a stale false only snapshots more). A `true` answer must be correct: the node is frozen, is a plain object/array (Object.prototype or null proto, or Array), and every data-property descendant (via Object.getOwnPropertyDescriptors values, including symbol keys) is deep-immutable; Map/Set/Date/RegExp/ArrayBuffer/typed arrays => false; non-plain class instances / functions are skipped (treated immutable) exactly as today.
2. In capturePassState keep the same records and the same restore closure behaviour. Micro-optimize only where semantics are identical (e.g. avoid re-checking isDeepImmutable for primitives).
3. Keep the PERF-PROBE lines (globalThis.__hexPerfProbe) working.
